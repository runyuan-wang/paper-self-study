# 自学：让理解从读者身上发生

## 何时读 / 输入 / 产出
何时：用户要自学、卡点、复述、组会准备或想记住关键机制。
输入：已核论文与关键解释、读者目标/基础/已有回答（不要重复问已知信息）。证据分类依 [证据模块](../evidence/SKILL.md)。
产出：一个当前学习闭环、分层自测、延后答案、卡点及续学入口。没有读者作答时只说“练习已准备”，不说“已学会”。

## 短循环
1. 先给一张心中地图：解决什么问题→关键改变→支撑证据→不能外推什么。术语只在下一步要用时引入，不默认数学基础很强或默认万字。
2. 展示一个具体情境，请读者猜下一步/哪一步与旧法不同。允许跳过作答直接读解释，不以考试阻断帮助。
3. 按 [机制模块](../mechanism/SKILL.md) 讲关键一步，再请读者用自己的话复述或改一个输入重算。
4. 针对实际回答定位错误：概念不清/符号不清/规则不清/算术错误/证据外推。每次只补最小相关段，再回到当前问题。
5. 收：留一句已确认理解、一处未懂、下次从哪一步继续。没有新反馈不自动生成更多课程、催答或提醒。

## 自测按深度选择，不全套强塞
- 基础：这篇要解决哪个现实问题？F的证据在哪里？
- 机制：给同一输入，第一处分叉在何处？修改一个条件会怎样？允许回答“材料不足”。
- 判断：哪些是E示例/哪些是H外推？为什么某个结果不能直接支持因果、等效或普遍优越？
- 迁移：换人群/规模/输入，哪些前提改变？需要新证据才能应用哪部分？
每题给合理答案与依据，接受多个有证据的解释，不编唯一正确意见。
答案放在题后独立“核对答案”区域或HTML折叠区，不先把答案写进问题。

## 构造例配套练习
这不是论文实验：等权平均与加权汇总，输入(2,8)，权重(0.25,0.75)。
题1：各输出多少，差异在哪一步？题2：输入变(4,4)会怎样？题3：加权结果更大能说明更准确吗？
核对答案：5与6.5，分叉在权重；两者都是4；不能，缺目标/误差和真实数据。算法教学题不能转临床建议。

## 反馈与验收
首次真正使用后问一个聚焦问题：“哪一步仍讲不通？”或“能否不看答案解释关键一步？”具体反馈回到相应模块，不把私密原话拷进可分享skill。
独立复述、重算和识别边界是理解线索，不是严谨学习效果试验；用户未回答则记未知。自测答案必须能从已核材料或明标E/D过程得到，不能引入新未经核事实。
